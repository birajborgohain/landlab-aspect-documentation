September, 11, 2026: Sediment Deposit Thickness in Landlab ``SimpleSubmarineDiffuser``
==========================================================================================

Purpose
-------

This document summarizes the discussion of the Landlab
``sediment_deposit__thickness`` field, its relationship to
``SimpleSubmarineDiffuser`` and ``LinearDiffuser``, the role of sediment
volume flux, and the meaning and limitations of
``method="resolve_on_patches"`` in the context of Landlab--ASPECT coupling.

The discussion is based primarily on the ``SimpleSubmarineDiffuser`` and
``LinearDiffuser`` source code examined in this work.

1. ``sediment_deposit__thickness``: what is the field?
-------------------------------------------------------

``SimpleSubmarineDiffuser`` creates the field if it does not already exist:

.. code-block:: python

   if "sediment_deposit__thickness" not in grid.at_node:
       grid.add_zeros("sediment_deposit__thickness", at="node")

The field is therefore a **node-based Landlab field**.

Its ``_info`` entry is:

.. code-block:: python

   "sediment_deposit__thickness": {
       "intent": "out",
       "units": "m",
       "mapping": "node",
   }

The important point is that this field is an **output diagnostic**.  It is
not an independently evolved sediment-layer state variable in
``SimpleSubmarineDiffuser``.

2. How ``sediment_deposit__thickness`` is calculated
----------------------------------------------------

At the beginning of every ``run_one_step(dt)``, the component makes a copy of
the current topography:

.. code-block:: python

   z_before = self.grid.at_node["topographic__elevation"].copy()

The diffuser then calculates its diffusivity and calls the inherited
``LinearDiffuser.run_one_step(dt)``:

.. code-block:: python

   self.calc_diffusion_coef()
   super().run_one_step(dt)

After the inherited diffuser has changed ``topographic__elevation``, the
component calculates:

.. code-block:: python

   depo[:] = (
       self.grid.at_node["topographic__elevation"] - z_before
   )

Therefore,

.. math::

   H_{deposit} = z_{after} - z_{before}.

This means:

* positive ``sediment_deposit__thickness`` = increase in elevation
  (deposition),
* negative ``sediment_deposit__thickness`` = decrease in elevation
  (erosion),
* approximately zero = little or no net topographic change during that
  timestep.

The field represents the **net topographic change generated by the
diffuser during the most recent call to ``run_one_step``**.

It should therefore not automatically be interpreted as the total,
cumulative sediment thickness stored in the model.

3. Why the diffuser is fundamentally a volume-flux model
---------------------------------------------------------

The inherited ``LinearDiffuser`` represents diffusive sediment transport
using a sediment volume flux on grid links.

The component provides the field:

.. code-block:: python

   "hillslope_sediment__unit_volume_flux"

with the description:

   Volume flux per unit width along links

The basic diffusion relationship is:

.. math::

   q_s = -K \nabla z,

where:

* :math:`q_s` is sediment volume flux,
* :math:`K` is linear diffusivity,
* :math:`\nabla z` is the topographic gradient.

The flux is calculated on links, while elevation is stored on nodes.

The model then calculates the divergence of sediment flux at nodes:

.. math::

   \frac{\partial z}{\partial t}
   =
   -\nabla \cdot q_s.

Substituting the diffusive flux gives the continuum diffusion equation:

.. math::

   \frac{\partial z}{\partial t}
   =
   \nabla \cdot (K\nabla z).

The actual elevation update is approximately:

.. math::

   z^{n+1}
   =
   z^n
   +
   \frac{\partial z}{\partial t}\Delta t.

Consequently, ``sediment_deposit__thickness`` is obtained **after this
transport calculation** by measuring the resulting elevation change.

4. The ``SimpleSubmarineDiffuser`` pathway
------------------------------------------

The overall calculation can be summarized as:

.. code-block:: text

   topographic__elevation
            |
            v
       water depth
            |
            v
        diffusivity K
            |
            v
       LinearDiffuser
            |
            v
     topographic gradient
            |
            v
       sediment flux
            |
            v
     flux divergence
            |
            v
          dz/dt
            |
            v
       new elevation
            |
            v
   sediment_deposit__thickness

The submarine diffuser first determines water depth from sea level and
topography:

.. math::

   h = SL - z.

It then calculates a depth-dependent diffusivity.

For shallow water, the diffusivity is based on the tidal-depth function.
For water deeper than the wave base, the diffusivity is exponentially
reduced.  Land receives a very small diffusivity value to avoid numerical
issues.

Conceptually:

.. math::

   K(h)
   =
   K_{shallow} f(h)

for shallow water, with an additional exponential reduction below the wave
base for sufficiently deep water.

The resulting ``kd`` field is then supplied to ``LinearDiffuser``.

5. The role of ``kd`` in ``SimpleSubmarineDiffuser``
----------------------------------------------------

``SimpleSubmarineDiffuser`` creates a node field called ``kd`` if it does
not already exist:

.. code-block:: python

   if "kd" not in grid.at_node:
       grid.add_zeros("kd", at="node")

The constructor then makes ``LinearDiffuser`` use this field:

.. code-block:: python

   kwds.setdefault("linear_diffusivity", "kd")

Thus, in the normal ``SimpleSubmarineDiffuser`` setup:

.. code-block:: text

   SimpleSubmarineDiffuser
           |
           | calculates kd at nodes
           v
       grid.at_node["kd"]
           |
           | LinearDiffuser maps node K to links
           v
       link diffusivity
           |
           v
       sediment volume flux
           |
           v
       elevation change

This distinction becomes important when considering
``resolve_on_patches``.

6. ``method="simple"`` in ``LinearDiffuser``
--------------------------------------------

The default ``LinearDiffuser`` method is:

.. code-block:: python

   method="simple"

In this branch, if diffusivity is defined at nodes, it is mapped to links.
The source uses:

.. code-block:: python

   kd_links = self._grid.map_max_of_link_nodes_to_link(self._kd)

Thus the link diffusivity is determined from the node diffusivities using
the maximum of the two endpoint values.

The basic calculation is then:

.. code-block:: python

   sediment_flux[mg.active_links] = (
       -kd_activelinks * gradient[mg.active_links]
   )

followed by:

.. code-block:: python

   mg.calc_flux_div_at_node(
       sediment_flux,
       out=self._dqsds
   )

and:

.. code-block:: python

   dzdt = -self._dqsds

This is a direct link-based finite-difference/finite-volume-style
diffusion calculation.

7. What ``resolve_on_patches`` means
------------------------------------

``resolve_on_patches`` is a **different numerical representation of the
diffusion flux**.

It does **not** mean that Landlab is switching from a continuum sediment
model to a particle sediment model.

The source documentation describes the method as mapping both slopes and
diffusivities onto patches, solving there, and then resolving the values
back to the nodes.

A key difference is that ``resolve_on_patches`` treats diffusivity as a
field with directionality.  Therefore diffusivity must be defined on links.

The constructor explicitly checks this:

.. code-block:: python

   if self._use_patches and not self._kd_on_links:
       raise ValueError(
           "if using the resolve_on_patches method, linear_diffusivity"
           " must be defined at links."
       )

It also requires a ``RasterModelGrid``.

Thus:

.. code-block:: text

   resolve_on_patches
          |
          +-- RasterModelGrid required
          |
          +-- K must be defined on links
          |
          +-- directional K is honored
          |
          +-- patch gradients are used
          |
          +-- flux is resolved back to links
          |
          +-- flux divergence is calculated at nodes
          |
          +-- elevation is updated

8. What a patch means here
--------------------------

A patch is a local spatial element of the raster grid.  In this algorithm,
patches are accessed through Landlab grid relationships such as:

.. code-block:: python

   mg.patches_at_link
   mg.patches_present_at_link

The algorithm also uses:

.. code-block:: python

   mg.calc_grad_at_patch(z)

to calculate the x- and y-components of the topographic gradient associated
with patches.

For a conceptual raster cell:

.. code-block:: text

       o-------------o
       |             |
       |    patch    |
       |             |
       o-------------o

The important distinction is:

.. code-block:: text

   Landlab patch
       = spatial/numerical grid element

   ASPECT particle
       = material/compositional representation

These are not the same concept.

9. What ``resolve_on_patches`` actually calculates
---------------------------------------------------

The branch begins with:

.. code-block:: python

   slx = mg.zeros("link")
   sly = mg.zeros("link")

It first retains ordinary link gradients for the corresponding horizontal
and vertical links:

.. code-block:: python

   slx[self._hoz] = gradient[self._hoz]
   sly[self._vert] = gradient[self._vert]

It then calculates patch gradients:

.. code-block:: python

   patch_dx, patch_dy = mg.calc_grad_at_patch(z)

The patch gradients are averaged onto the appropriate links to construct
``slx`` and ``sly``.

The magnitude of the reconstructed slope is then:

.. math::

   C_{slope}
   =
   \sqrt{sl_x^2 + sl_y^2}.

The method also constructs directional diffusivities:

.. code-block:: python

   Kx = mg.zeros("link")
   Ky = mg.zeros("link")

and averages neighboring link diffusivities where appropriate.

The resulting diffusivity magnitude is:

.. math::

   |K|
   =
   \sqrt{K_x^2 + K_y^2}.

The flux magnitude is then formed from:

.. code-block:: python

   flux_links = v * Cslope

or conceptually:

.. math::

   |q| = |K|\,|\nabla z|.

The code calculates an angle from the x and y slope components and projects
the flux onto horizontal and vertical links using cosine and sine factors.

Finally:

.. code-block:: python

   sediment_flux[mg.active_links] = -flux_links[mg.active_links]

and the flux divergence is calculated:

.. code-block:: python

   self._grid.calc_flux_div_at_node(
       sediment_flux,
       out=self._dqsds
   )

Thus ``resolve_on_patches`` still ends with the same basic physical
sequence:

.. math::

   z
   \rightarrow
   \nabla z
   \rightarrow
   q_s
   \rightarrow
   \nabla\cdot q_s
   \rightarrow
   \frac{\partial z}{\partial t}
   \rightarrow
   \Delta z.

10. What ``resolve_on_patches`` does NOT do
--------------------------------------------

There is no particle calculation in the ``resolve_on_patches`` branch.

The branch contains no operation that:

* reads ASPECT particles,
* counts particles,
* calculates particle mass,
* calculates particle volume,
* calculates particle concentration,
* converts particle composition to sediment thickness, or
* creates ``sediment_deposit__thickness`` directly from particles.

Therefore:

.. code-block:: text

   resolve_on_patches
          !=
   particle sediment model

It is a numerical method for the **continuum diffusion calculation**.

11. Relationship to ``sediment_deposit__thickness``
----------------------------------------------------

The important distinction is:

.. code-block:: text

   sediment volume flux
             |
             v
      flux divergence
             |
             v
         elevation change
             |
             v
   sediment_deposit__thickness

Therefore ``sediment_deposit__thickness`` is downstream of the diffusion
calculation.

It is not itself the sediment transport mechanism.

In the current implementation:

.. math::

   H_{deposit}
   =
   z_{after}-z_{before}.

This means the field reports what happened to the topographic surface as a
result of the diffuser.

12. Implication for Landlab--ASPECT coupling
--------------------------------------------

This distinction is important for the observed difference between ASPECT
composition methods.

Suppose the coupling uses:

.. code-block:: text

   ASPECT
      |
      +-- Field composition
      |
      v
   sediment information
      |
      v
   Landlab topography / sediment field
      |
      v
   SimpleSubmarineDiffuser
      |
      v
   sediment flux
      |
      v
   elevation change
      |
      v
   sediment_deposit__thickness

If the Field composition setup produces sediment but the Particle
composition setup does not, the absence of sediment in
``sediment_deposit__thickness`` does not by itself demonstrate that the
diffusion equation cannot work with particles.

A more likely diagnostic question is:

.. code-block:: text

   ASPECT Particle composition
            |
            v
   Is sediment amount/composition
   correctly extracted?
            |
            v
   Is it converted to the quantity
   expected by the coupling?
            |
            v
   Does Landlab topographic elevation
   or sediment thickness change?
            |
            v
   Does LinearDiffuser calculate flux?
            |
            v
   Does flux divergence produce dz?
            |
            v
   Does sediment_deposit__thickness
   become nonzero?

The exact point where the Particle and Field cases diverge needs to be
identified in the coupling code.

13. Why changing to ``resolve_on_patches`` is not automatically the solution
-----------------------------------------------------------------------------

Changing:

.. code-block:: python

   method="simple"

to:

.. code-block:: python

   method="resolve_on_patches"

changes the numerical diffusion branch.

It does not activate a particle-to-thickness conversion.

There is also a direct compatibility issue for the current
``SimpleSubmarineDiffuser`` implementation:

* ``SimpleSubmarineDiffuser`` creates ``kd`` at nodes.
* ``resolve_on_patches`` requires ``linear_diffusivity`` to be defined at
  links.

Therefore simply adding:

.. code-block:: python

   method="resolve_on_patches"

may result in a diffusivity-location error unless the coupling/component is
also changed so that the diffusivity supplied to ``LinearDiffuser`` is
link-based.

15. Key conclusions
-------------------

The main conclusions from the discussion are:

#. ``sediment_deposit__thickness`` is a node-based output field of
   ``SimpleSubmarineDiffuser``.

#. It is calculated as the difference between topography after and before
   the diffuser timestep:

   .. math::

      H_{deposit}=z_{after}-z_{before}.

#. The field is therefore a **diagnostic of net topographic change**, not an
   independently solved sediment-particle thickness field.

#. ``LinearDiffuser`` is fundamentally based on sediment **volume flux**:

   .. math::

      q_s=-K\nabla z.

#. Flux divergence produces erosion/deposition:

   .. math::

      \frac{\partial z}{\partial t}
      =
      -\nabla\cdot q_s.

   The resulting elevation change is what becomes
   ``sediment_deposit__thickness``.

#. ``resolve_on_patches`` changes the numerical representation of the
   diffusion flux by using patch gradients and directional link
   diffusivities.

#. ``resolve_on_patches`` does **not** convert ASPECT particles into
   sediment thickness.

#. ``resolve_on_patches`` requires a ``RasterModelGrid`` and link-based
   diffusivity.

#. The current ``SimpleSubmarineDiffuser`` setup normally generates ``kd``
   at nodes, so using ``resolve_on_patches`` requires additional attention
   to the diffusivity representation.

#. Therefore, if ASPECT ``composition field = Field`` produces sediment but
   ``composition field = Particle`` does not, the critical investigation is
   the **Particle -> sediment amount/thickness -> Landlab field** transfer
   pathway, rather than assuming that ``resolve_on_patches`` will activate
   particle sediment transport.

FastScape Sediment Thickness and Deposition
----------------------------------------------

Purpose
-------

This document summarizes the FastScape-focused investigation of sediment
thickness and sediment deposition, with particular attention to how these
concepts differ from the Landlab ``SimpleSubmarineDiffuser`` formulation.

The goal is to establish the mathematical meaning of sediment thickness
before tracing the ASPECT--FastScape coupling, especially the mechanism by
which an ASPECT particle/composition representation can result in sediment
being produced in a FastScape--ASPECT experiment.

1. FastScape sediment modeling: the central distinction
--------------------------------------------------------

The most important distinction is between:

* **net surface-elevation change during a timestep**, and
* **the persistent thickness of an active sediment layer**.

For Landlab ``SimpleSubmarineDiffuser``:

.. math::

   H_{deposit}=z_{after}-z_{before}.

This is a diagnostic of the net topographic change produced by the diffuser
during the latest timestep.

FastScape explicitly distinguishes surface elevation from
basement/bedrock elevation and represents an active sediment layer.

Conceptually:

.. math::

   H_s=h-h_{base},

where :math:`h` is surface elevation and :math:`h_{base}` is
basement/bedrock elevation.

2. FastScape surface, basement, and sediment layer
---------------------------------------------------

The FastScape sediment model tracks the topographic surface and bedrock,
separated by an active sediment layer.

.. code-block:: text

                 surface h
                    |
                    |
              sediment layer
                    |
                    |
              basement h_base

Therefore:

.. math::

   H_s=h-h_{base}.

This provides a persistent measure of how much sediment overlies the
basement.

The FastScape Python API also exposes ``surf_elevation``,
``bedrock_elevation``, and ``thickness`` in its sediment-layer process.

3. Difference from Landlab ``sediment_deposit__thickness``
-----------------------------------------------------------

The two quantities should not be treated as equivalent.

Landlab:

.. math::

   H_{deposit}^{Landlab}=z^{n+1}-z^n.

FastScape active sediment layer:

.. math::

   H_s^{FastScape}=h-h_{base}.

The Landlab quantity asks:

   How much did the surface elevation change during this diffusion step?

The FastScape quantity asks:

   How much sediment currently lies between the surface and the
   basement/bedrock?

Thus:

.. math::

   H_{deposit}^{Landlab}\ne H_s^{FastScape}

in general.

4. FastScape sediment thickness affects the physics
----------------------------------------------------

FastScape provides different coefficients for sediment and bedrock,
including quantities such as:

.. code-block:: text

   kf
   kfsed
   kd
   kdsed
   g
   gsed

Conceptually:

.. code-block:: text

                    H_s = h - h_base
                           |
                 +---------+---------+
                 |                   |
              H_s ~ 0              H_s > 0
                 |                   |
                 v                   v
              BEDROCK             SEDIMENT
                 |                   |
                 v                   v
               kf, kd, g          kfsed, kdsed, gsed

Thus sediment thickness is not merely an output; it can determine which
material/process parameters apply.

5. Continental FastScape sediment deposition
--------------------------------------------

For continental sediment transport, FastScape extends the classical Stream
Power Law to include sediment transport and deposition.

A conceptual form is:

.. math::

   \frac{\partial h}{\partial t}
   =
   U
   -
   K_f A^m S^n
   +
   \frac{G}{A}
   \int_A
   \left(
   U-\frac{\partial h}{\partial t}
   \right)dA.

The terms represent, conceptually:

* :math:`U` -- uplift,
* :math:`K_f A^m S^n` -- fluvial incision/erosion,
* :math:`A` -- upstream drainage area,
* :math:`S` -- channel slope,
* :math:`G` -- sediment deposition/transport parameter,
* the integral -- net sediment production associated with the upstream
  drainage area.

The important addition is the upstream sediment-supply term.

6. Meaning of the upstream integral
------------------------------------

The deposition term contains:

.. math::

   \int_A
   \left(
   U-\frac{\partial h}{\partial t}
   \right)dA.

Conceptually, this represents sediment generated by net erosion over the
upstream drainage area.

The model therefore has a source-to-sink structure:

.. code-block:: text

             upstream landscape
                    |
          +---------+---------+
          |                   |
       erosion             erosion
          |                   |
          +---------+---------+
                    |
                    v
             sediment supply
                    |
                    v
               downstream
                    |
                    v
                deposition

This differs from a purely local diffusion formulation because local
deposition can depend on sediment generated upstream.

7. Landlab diffusion versus FastScape sediment transport
---------------------------------------------------------

Landlab ``LinearDiffuser`` uses:

.. math::

   q_s=-K\nabla z,

followed by:

.. math::

   \frac{\partial z}{\partial t}
   =
   -\nabla\cdot q_s.

Therefore:

.. math::

   \frac{\partial z}{\partial t}
   =
   \nabla\cdot(K\nabla z).

The pathway is:

.. code-block:: text

   topography
       |
       v
   local gradient
       |
       v
   diffusivity
       |
       v
   sediment volume flux
       |
       v
   flux divergence
       |
       v
   elevation change
       |
       v
   sediment_deposit__thickness

FastScape instead combines sediment supply, deposition, and a persistent
surface/bedrock distinction.

8. Marine FastScape formulation
-------------------------------

The marine part is especially relevant to the Landlab--ASPECT problem.

The FastScape marine formulation includes a surface-evolution equation of
the conceptual form:

.. math::

   \frac{\partial h}{\partial t}
   =
   K_M\nabla^2 h
   +
   \mathbf{v}\cdot\nabla h
   +
   Q_s
   +
   R_M.

The terms discussed are:

* :math:`K_M` -- marine sediment transport coefficient,
* :math:`\nabla^2h` -- diffusive component,
* :math:`\mathbf{v}` -- horizontal transport/advection velocity,
* :math:`Q_s` -- sediment supply from the continental domain,
* :math:`R_M` -- marine source/sink contribution.

The important feature is :math:`Q_s`: marine deposition can receive sediment
supplied from the continental domain.

9. Marine source-to-sink behavior
---------------------------------

The marine pathway can be visualized as:

.. code-block:: text

             CONTINENT
                 |
              erosion
                 |
                 v
          river sediment flux
                 |
                 v
             shoreline
                 |
                Q_s
                 |
                 v
             MARINE
                 |
                 v
        marine sediment transport
                 |
                 v
             deposition

Thus FastScape's marine sediment system is not simply a local calculation of
``-K * gradient``.  It contains sediment supplied from the continental
system.

10. Grain-size-dependent marine sediment
----------------------------------------

The marine model distinguishes sediment types, including silt and sand.

Different grain sizes can have different:

* transport coefficients,
* porosity,
* compaction behavior,
* deposition behavior.

FastScapeLib exposes parameters associated with silt and sand, including
reference porosities, characteristic porosity depths, silt fraction, and
separate marine diffusivities.

Conceptually:

.. code-block:: text

              sediment supply
                    |
             +------+------+
             |             |
            silt          sand
             |             |
             v             v
         K_silt         K_sand
         porosity       porosity
         compaction     compaction
             |             |
             +------+------+
                    |
                    v
              marine deposit

This is substantially richer than a single scalar sediment thickness field.

11. Compaction and geometric thickness
--------------------------------------

FastScape's marine model includes sediment compaction.

Therefore a distinction must be made between:

* sediment volume supplied,
* sediment volume deposited,
* compacted geometric layer thickness.

A surface change

.. math::

   \Delta h=10\ {\rm m}

does not automatically mean that exactly 10 m of uncompacted sediment was
added.  Porosity and compaction can change the relationship between
deposited sediment volume and final geometric thickness.

This is another reason not to identify FastScape sediment thickness with the
Landlab diagnostic :math:`z^{n+1}-z^n`.

12. Stratigraphic thickness in FastScape
-----------------------------------------

FastScapeLib also contains explicit stratigraphic functionality.

Relevant quantities include:

.. code-block:: text

   ThicknessToNextHorizon
   ThicknessToBasement
   DepositionalBathymetry
   DepositionalSlope
   DistanceToSHore
   HorizonAge
   ThicknessErodedBelow
   Sand/ShaleRatio

In particular:

``ThicknessToNextHorizon``
   Sediment thickness between the current horizon and the next horizon.

``ThicknessToBasement``
   Total sediment thickness between a horizon and the basement.

FastScape can therefore represent more than the latest timestep's
deposition; it can preserve a stratigraphic history.

13. Three different thickness concepts
---------------------------------------

The investigation identified three related but distinct concepts.

A. Instantaneous surface change

.. math::

   \Delta h=h^{n+1}-h^n.

B. Active sediment-layer thickness

.. math::

   H_s=h-h_{base}.

C. Stratigraphic thickness

For a horizon, thickness to the next horizon is the vertical separation
between those horizons; total thickness to basement is the corresponding
distance from the horizon to the basement.

These quantities should not be conflated.

15. The central mathematical difference
---------------------------------------

Landlab:

.. math::

   q_s=-K\nabla z

followed by:

.. math::

   \frac{\partial z}{\partial t}
   =
   -\nabla\cdot q_s,

and then:

.. math::

   H_{deposit}=z^{n+1}-z^n.

FastScape:

.. math::

   H_s=h-h_{base}

is an active sediment-layer quantity, while erosion, transport, deposition,
and marine processes evolve the surface and sediment/bedrock state.

Thus the conceptual structures are:

Landlab:

.. code-block:: text

   z^n
   |
   v
   diffusive flux
   |
   v
   z^(n+1)
   |
   v
   z^(n+1) - z^n

FastScape:

.. code-block:: text

   surface h + basement h_base
              |
              v
       sediment thickness
              |
              v
      sediment/bedrock physics
              |
              v
    erosion/transport/deposition
              |
              v
       updated surface/state

16. Why this matters for ASPECT Particle versus Field
------------------------------------------------------

The current investigation is motivated by the observation that an ASPECT
coupling using:

.. code-block:: text

   composition field = Field

can produce sediment, while the corresponding:

.. code-block:: text

   composition field = Particle

case does not currently produce sediment in the Landlab--ASPECT setup.

The FastScape results suggest that the critical issue may not simply be
whether the diffusion solver can operate on a particle representation.

Instead, we need to determine how ASPECT material/composition information is
converted into the FastScape sediment state.

The conceptual FastScape pathway is:

.. code-block:: text

       ASPECT material/composition
                  |
                  v
          sediment information
                  |
                  v
          FastScape surface h
                  |
                  +
          FastScape basement h_base
                  |
                  v
        H_s = h - h_base
                  |
                  v
        sediment/bedrock state
                  |
                  v
       erosion/transport/deposition

The corresponding Landlab pathway currently being investigated is:

.. code-block:: text

       ASPECT composition
              |
              v
       ??? sediment transfer ???
              |
              v
       Landlab topographic__elevation
              |
              v
       SimpleSubmarineDiffuser
              |
              v
       volume flux
              |
              v
       flux divergence
              |
              v
       elevation change
              |
              v
       sediment_deposit__thickness

The ``??? sediment transfer ???`` step is therefore a critical point to
inspect.

17. Important conclusion about particles
----------------------------------------

The FastScape documentation examined so far does **not** establish that
FastScape itself is a particle sediment model.

The important finding is instead that FastScape has a sediment state and
sediment-aware physics:

.. code-block:: text

   surface
   basement
   sediment thickness
   sediment properties
   marine transport
   compaction
   stratigraphy

Therefore:

   "FastScape works with particles"

should not yet be interpreted as:

   "FastScape calculates sediment thickness directly from particles."

The actual ASPECT--FastScape coupling code must be inspected to determine
exactly how ASPECT particle/material information is transferred into
FastScape's surface, basement, or sediment state.

18. Current working hypothesis
------------------------------

The strongest working hypothesis from this stage is:

.. code-block:: text

   FastScape has an explicit sediment/bedrock state
                    |
                    v
        sediment thickness is persistent
                    |
                    v
      sediment state affects process physics
                    |
                    v
     composition/material information can
       potentially be incorporated into it

whereas:

.. code-block:: text

   Landlab SimpleSubmarineDiffuser
                    |
                    v
          calculates volume flux
                    |
                    v
          changes topography
                    |
                    v
     sediment_deposit__thickness =
             z_after - z_before

Therefore the observed Field-versus-Particle difference in the
Landlab--ASPECT framework may be associated with the **coupling/interface
that transfers ASPECT material information into a sediment state**, rather
than with the numerical diffusion equation itself.

This remains a hypothesis until the ASPECT--FastScape coupling source code is
examined.

19. Next code-investigation target
----------------------------------

The next step is to inspect the ASPECT--FastScape coupling itself.

The specific quantities to trace are:
